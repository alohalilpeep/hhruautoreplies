# Бэклог

Накопившееся, что отложено сознательно. Не приоритет.

## Требует твоего участия

- **Девять чатов ждут ответа.** `venv/bin/python hh_chats.py --attention`
  покажет актуальный список. Самые горячие: Биорайз (прямой телефон) и
  Норникель (предлагают созвон). Отвечает человек, скрипт только помечает.

- **Вопросы без ответа.** Часть вакансий висит в `questions`, потому что на
  их вопросы нет одобренного текста или выбора. Разбор: `hh_answers.py
  --export`, `hh_choices.py --export`.

- **Противоречие про сетевое железо.** В ответе для Positive Technologies
  стоит «сетевое оборудование не настраивал», а позже выяснилось, что опыт
  есть. Пока не уточнено какое именно железо и в каком объёме — блок не
  трогаем, иначе в разные отклики уедут противоречащие ответы. Затрагивает
  4 вопроса: MikroTik, эксплуатация сетевого оборудования, настройка через
  CLI, маршрутизатор с нуля.

- **Незаполненные цифры в резюме.** Добавлено «13 сервисов, 4 окружения».
  Остались метки: количество политик Kyverno, процент сокращения логов,
  число автотестов, количество баз в бэкапах.

## Технический долг

- **Разные формулировки одного варианта.** Банк хранит один выбор на вопрос,
  а работодатели подписывают по-разному: «Удаленно», «Удаленка», «Полностью
  удаленный (Все города РФ)». При несовпадении вакансия откладывается —
  правится вручную одной строкой в базе. Полное решение — хранить выбор по
  паре «вопрос + набор вариантов», то есть отдельной таблицей. Пока случай
  единственный, поэтому не делаем.

- **Свои сообщения в `chat_messages`.** hh не помечает автора у исходящих,
  поэтому наши сопроводительные письма попадают в таблицу как входящие.
  В отчётах отфильтрованы по началу письма, но в сырых данных лежат. Туда же
  попадают элементы интерфейса вроде «Добавить сопроводительное».

- **Качество сопоставления в когортах.** `hh_stats.py --collect` находит
  примерно половину откликов. Причины известны и воспроизведены:
  1. В базе компания с правовой формой («ООО БУЛАТ»), в списке откликов —
     без неё («БУЛАТ»), плюс неразрывный пробел.
  2. hh показывает в списке откликов название вакансии без грейда.

  Решение понятно: срезать правовую форму регуляркой и прогонять обе стороны
  через существующий `clean_title()`. Точного id вакансии в списке нет —
  заголовок там `<span>`, ссылка только на работодателя, поэтому сопоставление
  останется по паре «компания + название».

- **Дубли откликов.** На одну и ту же вакансию можно откликнуться дважды, если
  работодатель опубликовал её под разными id. Так вышло с «Системный
  администратор мобильных устройств» в Т-Банк — отклик ушёл 14 и 15 сентября.
  Дедупликация сейчас только по id вакансии, нужна проверка по паре
  «компания + название».

- **Стоп-лист по названию вакансии.** Из-за семантического расширения поиска
  в выдачу лезут Python Developer, Data Engineer и стажёры QA. Стоп-лист по
  компаниям есть (`blacklist.txt`), по названию вакансии — нет.

- **Ежедневный слепок статистики.** Сейчас `hh_stats.py --snapshot` руками.
  Можно повесить на launchd рядом с подъёмом резюме — тогда динамика
  «отказов за сутки» будет считаться сама.

## Идеи

- **Сцепка в один цикл.** Поднять резюме → автоотклики → добрать чаты →
  слепок статистики. Сейчас это четыре ручные команды. Нужен один вход,
  который не запускает следующий шаг, если предыдущий упал, и держит один
  профиль BitBrowser на весь цикл вместо четырёх открытий подряд.

- **Перенос на VPS через AdsPower.** BitBrowser только под Windows и macOS,
  AdsPower умеет Linux и headless — значит VPS за 5 долларов вместо 25.
  Переписать надо только `open_profile()` и `close_profile()`, остальное
  работает поверх CDP одинаково. Нужен резидентный прокси, иначе hh увидит
  датацентровый IP.

- **Расширение поиска.** Сейчас: DevOps OR SRE OR «системный администратор»,
  в названии, удалёнка + гибрид, опыт 3-6, Россия. Дальше можно снять
  `search_field=name` (втрое больше вакансий, но лезут бэкендеры) или
  добавить `moreThan6` по опыту.

## Сделано, не возвращаемся

- Обязательное сопроводительное письмо в анкетах работодателя.
- Клик по вариантам ответа: радиокнопки и чекбоксы.
- Добор отложенных вакансий из базы, а не только из выдачи.
- Полный обход чатов: было видно 300 из 568.
- Хранение и разметка всех сообщений из чатов.
- Отчёт «куда заглянуть» по чатам.

## Известные ограничения, менять не планируется

- **«Собеседование» на hh включает автоматический скрининг.** Сбер шлёт
  приглашение к ГигаРекрутеру всем откликнувшимся, РУСАЛ — ссылку на бота
  в Telegram. hh считает это собеседованием. Отличить от живого приглашения
  по счётчику нельзя.

- **Дата в списке откликов — это дата отклика, а не дата отказа.** Поэтому
  «сколько отказов пришло во вторник» ретроспективно не построить, только
  разницей между слепками.

- **Отметка «непрочитано» у чатов ненадёжна.** Чат, открытый руками в
  интерфейсе hh, её теряет, и для скрипта выглядит пустым. Опираемся на
  собственную базу, а не на отметку hh.

- **Скрипт работает внутри профиля BitBrowser.** Если мак уснёт или окно
  закроют, связь рвётся. Прогон останавливается сам, вакансии не теряются
  и вернутся на следующем запуске.
